# 第一章 顶层业务架构与标准规范

## 一、项目背景与建设目标

#### 1. 项目建设背景

**宏观战略与集团"十五五"低碳发展要求。** 在国家"碳达峰、碳中和"战略深入推进的宏观背景下，工业装备制造业正加速向全生命周期绿色化、数字化转型。特变电工电装集团作为我国输变电高端装备制造领域的龙头企业，坚决贯彻集团绿色低碳发展统一部署。根据集团"十五五"战略规划纲要，到 2028 年，电装集团须全面形成以"零碳园区、零碳工厂、零碳产品"为主线的绿色高质量发展模式，确保零碳园区全面建成并成为集团新的核心产业增长极。在此目标引领下，构建一套覆盖自身运营并向上下游产业链纵深辐射、具备高公信力与高效协同能力的碳足迹数字化管理生态系统，已成为支撑集团战略落地的关键路径。

**国际贸易绿色壁垒与合规实质性倒逼。** 随着全球绿色供应链竞争加剧，欧盟碳边境调节机制（CBAM）已进入实质性操作阶段，针对输变电产品及其原材料（钢、铝等）的直接与间接排放溯源监管日益严苛。电装集团产品大量服务于国内外重点工程及海外基础设施建设，亟需建立符合国际核算标准（如 ISO 14067、GHG Protocol 等）、支持全流程证据链追溯与多维溯源的产品碳足迹认证体系，打破国际绿色贸易壁垒，巩固全球竞争优势。

**数字化能碳运营现状与核心痛点。** 当前，电装集团绿色转型已进入深水区，但数字化支撑与集约化管控层面仍存在显著瓶颈：

- **能碳数据底座割裂，缺乏统一监管抓手**：集团下辖 18 个生产基地/园区所处区域广泛、生产工艺与用能结构各异，各单位能源计量统计口径、数据精度及碳排放管控标准不一致，数据孤岛严重，总部层面难以实现"一本账"穿透式监管和精准横向对标。
- **零碳评价无标可依，成效难以量化评估**：零碳园区建设缺乏统一、标准化的指标评价框架与动态打分体系，各单位降碳举措分散、效果参差不齐，难以形成可复制、可推广的绿色制造示范模式。
- **碳足迹核算成本高、周期长、证据链缺失**：传统的碳足迹核算高度依赖离线调研与第三方机构人工驻场，数据收集周期动辄数月，认证成本居高不下；且过程数据缺乏原始采样凭证与不可篡改的时间戳支撑，权威性易受质疑。
- **云边端协同能力薄弱，缺乏实时闭环调控**：现有系统多停留在"事后统计与静态展示"，边缘侧缺乏智能化数据采集、边缘计算与闭环控制机制，无法实现供能、储能、用能多要素的微秒级与秒级协同优化。

#### 2. 建设目标

本项目旨在通过"软硬件一体、云边端协同、管服一体化"的整体建设路径，研发构建"工厂—产业单位—总部"三级贯通的零碳集控运营系统与产品碳足迹集采管理认证一体化平台，实现对能源与碳排放"精准化计量、精细化管控、智能化决策、可视化呈现"。

**管理层级落地目标：**

| 管理层级 | 角色定位 | 核心落地目标 |
|:---|:---|:---|
| 集团总部层 | 监管与决策中心 | 打造集团能碳数据"驾驶舱"与统管枢纽，全面接入并统一管理 18 个园区的能碳运行态势；建立健全集团级能效对标体系与零碳园区评估模型，实现能耗异常穿透分析、减碳潜能挖掘与绿色转型成效的权威对外呈现 |
| 产业单位层 | 协同与治理中心 | 固化标准化的碳足迹数据采集、因子匹配与全过程核算流程，构建面向变压器、电缆、高低压开关等重点装备的行业级实景数据库（LCI），指导下属各生产经营单位科学编制降碳规划并精准落地技改措施 |
| 工厂车间层 | 执行与核算中心 | 沉淀标准因子集、计算模型规范及一键式认证申报模板等数字化工具包，配合边缘网关与控制器实现产线级与设备级数据自动采集，支撑各工厂快速响应客户低碳招投标与第三方合规认证需求，核算效率提升 50% 以上 |

**系统核心能力目标：**

- **计量精准化**：依托工业物联网架构与边缘调控一体机，打通产线 DCS、SCADA、能源表计等系统，消除数据盲区与统计偏差，实现核心能碳指标毫秒级/秒级高精度感知。
- **管控精细化**：建立覆盖原材料输入、生产加工、组装测试到包装出厂的装备产品全生命周期（Cradle-to-Gate）碳足迹追踪链路，形成不可篡改的碳排放数据追溯链。
- **决策智能化**：深度融合行业机理与 AI 优化算法，实现用能负荷精准预测、峰谷分时响应、多能互补协同调度与碳减排路径智能推荐。
- **呈现全景化**：打造集管控、运营、汇报于一体的 3D/多维数字化大屏，以生动图表与动态全景呈现集团双碳目标推进路径。

## 二、建设范围

本项目建设范围涵盖技术服务（标准与咨询）、软件研发、系统集成与数据治理、实施交付、硬件研制及供货部署五大板块，全面实现软硬件交钥匙工程。

- **技术服务范围（咨询、标准与数据体系研究）**
  - 能碳与园区管理标准构建：深入结合输变电制造行业工艺特征，完成特变电工电装集团零碳园区集控中心管理标准研制；梳理零碳园区、零碳工厂评价指标体系，形成分级评价准则与对标评估方案。
  - 产品碳足迹规范与管理体系：编制输变电装备（涵盖变压器、线缆、开关设备）碳足迹核算导则与管控规范，明确生命周期边界（系统边界、分配原则、截止准则等），研究符合 CBAM 政策及主流国际标准（ISO 14067）的实景数据采集与证据链管理体系。
  - 标准数据字典与接口规范梳理：制定集团统一度量衡的能碳物联数据字典、多源异构系统数据交互协议规范，梳理并设计集控中心与集采中心的核心 API 标准接口规范。
  - 装备制造专属因子库体系梳理：系统化完成变压器、线缆、开关等主营产品的上下游物料基础背景数据库梳理，梳理电力消耗、化石燃料、原材料专属因子集，支撑平台快速算碳。

## 三、双中心总体架构与协同机制

#### 1. 端—边—云三层物联网架构

| 层级 | 部署形态 | 核心职责 | 关键组件 |
|:---|:---|:---|:---|
| 端层（感知执行层） | 园区现场 | 能源介质与工艺参数物理量采集、设备状态感知与调控执行 | 数字电表、涡街/孔板流量计、温度压力变送器、智能仪表、变频器、储能 BMS |
| 边层（边缘计算层） | 园区机房/车间 | 协议转换、边缘计算、断点续传、本地闭环控制与告警预判 | 边缘调控一体机、IoT 采集网关、协议适配引擎（Modbus-TCP / MQTT / OPC-UA）、本地 SQLite 缓存 |
| 云层（平台应用层） | 集团私有云 | 时序数据存储、指标核算、业务应用、跨域协同与对报告输出 | 时序数仓（TimescaleDB）、业务主库（PostgreSQL）、指标计算引擎、双中心应用集群 |

#### 2. 双中心定位与协同

- **零碳园区集控中心（Monitor Center）**：面向"组织—能源—碳排放"的运行态管控，承担集团 18 园区能碳数据的统一采集、指标核算、对标分析与零碳评价，是集团能碳运行"驾驶舱"。
- **产品碳足迹集采中心（Footprint Center）**：面向"物料—工序—产品"的核算态管控，承担产品全生命周期 LCA 建模、因子匹配、认证签发与 CBAM 申报，是集团绿色贸易合规"通行证"。
- **协同赋能机制**：集控中心的能耗与工序实测数据是集采中心 LCA 制造加工阶段的核心输入；集采中心的单位产品碳足迹结果回流集控中心，作为零碳工厂自评估与对标管理的关键指标，形成"运行态数据反哺核算态模型、核算态结果约束运行态改进"的双向闭环。

## 五、文档编制范式：统一八段式模块模板

> 本文档自 v2.0.0 起，全部功能模块统一采用与「指标管控」模块一致的**八段式结构**，确保模块颗粒度对齐、字段级可研发、验收级可测试、跨模块可横向比对。编制者与评审者均须按此八段逐项校验完整性。

| 段序 | 段落名称 | 编制要求 | 缺失判定 |
|:---|:---|:---|:---|
| 【1】 | 定位与架构角色 | 明确模块功能定位、承载角色 Persona、页面路由/入口、上下游依赖与输出物 | 缺失即视为模块不完整，不得进入研发准入 |
| 【2】 | 业务场景与用户故事 | 业务场景一句话描述 + INVEST 合规用户故事（As a / I want / So that） | 缺失用户故事视为需求来源不可追溯 |
| 【3】 | 功能规格与交互契约 | 页面布局分区说明 + 交互规则逐条枚举，含筛选器、联动、钻取与刷新策略 | 缺失交互契约视为不可开发 |
| 【4】 | 页面字段字典与数据契约 | 字段级表格：序号 / 字段中文名称 / 数据类型 / 工程单位 / 校验与约束规则 | 字段无校验规则视为不可测试 |
| 【5】 | 核心数学模型与算法公式 | 公式卡片：核算公式 + 逻辑说明 + 变量定义与取值约定 | 涉及计算而无公式视为不可验收 |
| 【6】 | 展示、对标与判定口径 | 指标粒度、对比口径（同比/环比）、三色判定阈值、排名与达标规则 | 缺失判定口径视为结果不可解释 |
| 【7】 | 边界条件、异常处理与防错规则 | 除零、空值、越权、超时、并发、离线等异常的标准错误码与界面表现 | 缺失异常规则视为生产事故隐患 |
| 【8】 | QA 自动化验收准则（Gherkin BDD） | Given / When / Then 三段式可自动化执行的验收用例 | 缺失验收准则不得进入测试准入 |

**全局命名与格式约定：**

- 单位统一采用国家法定计量单位；能源折标统一采用 **GB/T 2589-2020** 当量/等价系数。
- 客观中立原则：全系统文字严禁出现"表现优异""落后单位""运行欠佳"等定性评语，统一以客观数值与时序环比（如 `同比 -2.4% ↓`）自解释。
- 状态自解释：状态仅由徽章、边框或色彩承载，严禁附加"已联动过滤""由于白名单未配置"等过程性说教文案。
- 除零安全兜底：任何分母为 0 的场景，前后端统一显示 `--`，严禁抛出 `NaN`、`Infinity` 或白屏。
