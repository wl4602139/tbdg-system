#### 【5】核心数学模型与算法框架

```math
EF_match = PRIORITY( Ecoinvent_exact, CLCD_approx, NDRC_fallback )
Q_mat_actual = Q_bom × ( 1 + R_loss )                     实际物料需求量（含工艺损耗）
E_raw = Σ ( Q_mat_actual × EF_mat )                       原材料阶段碳排
EF_match_level = LEVEL( EF_match )                        因子匹配层级（1=精确，3=兜底）
```

**变量定义与取值约定：** `EF_match` 遵循精确物料优先、本土近似次之、国家折标兜底的匹配优先级；匹配层级 1 为精确匹配，2 为本土近似，3 为兜底匹配，层级 3 时页面须标注"兜底因子"。

#### 【6】展示、对标与判定口径

- **分级口径**：原辅料因子标为 INTERNAL，Ecoinvent 跨境因子标为 SENSITIVE（含供应商来源）。
- **匹配口径**：匹配优先级固定为 Ecoinvent v3.8（精确物料）→ CLCD 0.2（本土近似）→ 国家发改委折标（兜底）。
- **证据口径**：本土实测因子必须附检测报告与第三方认证声明编号，二者缺一不可发布。
- **时效口径**：因子条目含 version_id、effective_from、effective_to，生效期外拦截选用。

#### 【7】边界条件、异常处理与防错规则

> ⚠️ 【研发设计红线与强约束校验】
> - 实测因子缺失检测报告或认证声明编号：发布按钮置灰，仅可保存为草稿。
> - 因子超出有效期：触发 `E_VAL_FACTOR_EXPIRED`，标注"因子待升级"并禁用选用。
> - Ecoinvent 授权到期：触发 `E_EXT_ECOINVENT_LICENSE`，自动降级使用 CLCD 因子兜底。
> - 溯源链条不完整（仅一级供应商以上为空）：标注"溯源待补充"，并降低该因子的可信度标识。

### 2. LCA 碳足迹核算引擎

#### 【1】定位与架构角色

- **功能定位**：产品全生命周期碳足迹核算的核心算法与状态机中枢，实现 BOM 层级自动展开、五大阶段滚算、工艺能耗分摊、报告状态流转与审计哈希存证。
- **承载角色**：P4 碳核算工程师（主操作）、P6 外部独立审计机构（核验）。
- **页面路由**：`/carbon-footprint/database/accounting`。
- **上游依赖**：ERP/PLM BOM、MES 工序四元组、实景数据库因子、因子库版本、审计哈希链。
- **下游输出**：LCA 报告、数字碳标签、CBAM 申报底数。

#### 【2】业务场景与用户故事

- **业务场景**：为出口欧盟的 220kV 变压器完成从 BOM 展开到五阶段滚算、再到内审核验与认证签发的全流程核算。
- **用户故事**：
  - As a **碳核算与认证工程师 (Persona P4)**，
  - I want **一键展开 BOM 并完成 ISO 14067 五阶段滚算，系统自动校验加总一致性与因子有效期**，
  - So that **我能快速产出经得起第三方审计与欧盟审查的碳足迹报告**。

#### 【3】功能规格与交互契约

**核心业务逻辑：**

- **BOM 层级自动展开**：从 ERP/PLM 自动拉取多级产品工程物料清单 (BOM)，计算物料损耗系数 $Q_{mat} = Q_{bom} × (1 + R_{loss})$。
- **5 大阶段 LCA 滚算模型**：严格依照 ISO 14067 标准执行生命周期评价滚算。
- **工艺能耗分摊**：基于工时或产量权重分摊真空干燥、退火炉等公共工序的水电气能耗。
- **状态机可视化**：以泳道图呈现 DRAFT → SUBMITTED → CERTIFYING → CERTIFIED → PUBLISHED → ARCHIVED 全链路。
- **审计哈希链展示**：逐节点展示计算过程哈希，尾节点校验 prev 引用，可在页面直观看到链条完整性。

**LCA 报告状态机（回捞 PRD-07）：**

| 当前状态 | 可触发动作 | 触发角色 | 审计写入 |
|:---|:---|:---|:---|
| DRAFT 草稿 | 提交内审 / 废弃 | P4 | 是 |
| SUBMITTED 送审 | 撤回（限内审驳回）/ 受理 | P4 + 机构 | 是 |
| CERTIFYING 认证中 | 不可编辑，仅审批 | — | 是 |
| CERTIFIED 已认证 | 一键发布 / 归档 | P4 + PM 联合 | 是 |
| PUBLISHED 已发布 | 归档 | PM | 是 |

- 审计哈希链（ADR-CF-003）：LCA 计算过程逐节点哈希存证，前一 hash 写入后一 hash 头部，尾节点校验 prev 引用，断裂触发 `E_AUDIT_HASH_BROKEN`。

- 因子匹配优先级：Ecoinvent v3.8（精确物料）→ CLCD 0.2（本土近似）→ 国家发改委折标（兜底）。

| 5 | 上游运输阶段碳排 | Decimal | kgCO2e | $Σ(吨公里 × 运输工具排放因子)$ |

| 7 | 试验检测阶段碳排 | Decimal | kgCO2e | 出厂耐压/温升试验用电碳排 |

| 12 | 工艺损耗率 | Decimal | % | 0 ≤ R_loss < 100% |

#### 【5】核心数学模型与算法框架

```math
E_PCF = E_raw + E_trans + E_manuf + E_test + E_pack
E_raw = Σ [ M_i × (1 + R_loss_i) × EF_mat_i ]                    原材料获取
E_trans = Σ [ M_i × D_i × EF_trans_mode ]                        上游运输
E_manuf = Σ [ ( E_process_energy / Batch_Output ) × EF_energy ]  制造加工
E_test = ( Q_test_elec / Test_Capacity ) × EF_grid               试验检测
E_pack = Σ [ M_pack_k × EF_pack_k ]                              包装出厂
Q_mat = Q_bom × ( 1 + R_loss )                                   物料损耗系数
Check: | C_total - Σ C_stage | <= 0.01 kgCO2e                    加总一致性自检
```

**变量定义与取值约定：** `M_i` 为物料净重（t）；`R_loss_i` 为工艺损耗率（%）；`EF_mat_i` 为物料实测碳因子（kgCO2e/kg）；`D_i` 为运输距离（km）；`EF_trans_mode` 为吨公里运输因子；`Q_test_elec` 为出厂试验用电量；`Test_Capacity` 为试验容量。核算边界为摇篮到大门（Cradle-to-Gate）。

#### 【6】展示、对标与判定口径

- **边界口径**：严格 Cradle-to-Gate 五阶段，阶段定义不可增减。
- **分配口径**：公共工序（真空干燥、退火炉）水电气能耗按工时或产量权重分摊，分配方法须在报告中声明。
- **容差口径**：总碳足迹与五阶段加总的容差上限 0.01 kgCO2e，超差即阻断证书签发。
- **状态口径**：认证中状态不可编辑；发布须 P4 + PM 联合签字。

#### 【7】边界条件、异常处理与防错规则

> ⚠️ 【研发设计红线与强约束校验】
> - 五阶段加总与总碳排容差超出 0.01 kgCO2e：触发 `E_CALC_LCA_SUM_MISMATCH`，后台阻断证书签发与对外发布并触发引擎重算。
> - 总碳足迹为负：触发 `E_VAL_LCA_TOTAL_NEGATIVE`，阻断保存。
> - 试验工时 $T_m = 0$：触发 `E_CALC_LCA_TDIV_ZERO`，阻断阶段算式生成。
> - 工序四元组不齐备：触发 `E_VAL_LCA_STAGE_INCOMPLETE`，阻断保存。
> - ERP BOM 超时：重试 3 次后降级使用本地缓存 BOM 快照，仅在 INV-FALLBACK 模式下允许手工上传 Excel BOM。
> - 哈希链断裂：触发 `E_AUDIT_HASH_BROKEN`，锁定当事单据并标记数据篡改。

### 3. 碳足迹报告与数字碳标签

#### 【1】定位与架构角色

- **上游依赖**：已认证的 LCA 报告、认证机构签章、报告哈希存证。
- **下游输出**：对外交付的认证报告 PDF、产品数字碳标签二维码。

#### 【2】业务场景与用户故事

- **业务场景**：产品出口发运前需随货提供双语碳足迹报告与可扫码验证的碳标签，供海外客户与海关查验。
- **用户故事**：
  - As a **碳核算与认证工程师 (Persona P4)**，
  - I want **一键导出中英双语 ISO 14067 报告并生成可扫码验真的数字碳标签二维码**，
  - So that **产品出口时能即时提供具备防伪能力的碳足迹证明**。

#### 【3】功能规格与交互契约

1. **双语报告导出**：一键导出符合 ISO 14067:2018 规范的双语（中、英文）官方碳足迹核算报告。

### 2. 关税申报模拟器

#### 【1】定位与架构角色

- **功能定位**：基于欧盟 ETS 碳价与国内已支付碳成本抵扣，测算出口欧盟产品的 CBAM 应缴碳关税，并支持多情景模拟与官方 XML 申报包导出。
- **承载角色**：P5 报关与关税专家。
- **页面路由**：`/carbon-footprint/cbam/declaration`。
- **上游依赖**：已认证 LCA 报告、EEX 碳价接口、国内碳市场价格、CBAM 官方默认值库。
- **下游输出**：CBAM Communication Template v2.1 官方 XML 申报包、关税成本测算报告。

#### 【2】业务场景与用户故事

- **业务场景**：向欧盟出口前测算碳关税成本，并在乐观/基准/悲观三种碳价情景下评估成本敞口与国内碳成本抵扣收益。
- **用户故事**：
  - As a **国际贸易与关税专家 (Persona P5)**，
  - I want **基于实时 ETS 碳价与国内已付碳成本测算应缴 CBAM 关税，并在多情景下对比成本敞口**，
  - So that **我能优化出口定价与国内碳成本抵扣策略，实现关税成本最小化**。

#### 【3】功能规格与交互契约

**关税模型：**

- **ETS 联动与情景模拟**（回捞 PRD-07 /《集采中心功能梳理 V1.0》"成本测算"）：
  - **ETS 碳价联动**：API 动态对接欧洲能源交易所（EEX）碳配额拍卖结算均价，刷新频率【待确认】（建议小时级）。
  - **多情景碳价模拟**：按欧盟当期碳价与情景碳价（乐观/基准/悲观）测算出口欧盟产品碳关税成本并对比。
  - **默认值回退**：无实测数据时一键套用 CBAM 官方各行业默认排放因子库完成估算。
  - **数据出境合规**：CBAM 申报数据跨境传输路径与审批【待补充：由信息安全合规组确认】。
- **核算流程**：
  1. **隐含碳强度核算**：测算出口单位产品直接与间接隐含碳强度 $Embedded\_Carbon$ (tCO2e/t)。
  2. **欧盟 ETS 实时碳价联动**：API 动态对接欧洲能源交易所 (EEX) 碳配额拍卖结算均价（€75 ~ €95/tCO2e）。
  3. **国内已支付碳成本抵扣**：严格计算在国内已承担的全国碳市场配额费用或绿电附加成本，依法申请等额抵扣。
  4. **官方 XML 申报包导出**：生成完全符合欧盟委员会 CBAM Communication Template v2.1 规范的结构化 XML 申报包。

#### 【4】页面字段字典与数据契约

| 序号 | 字段中文名称 | 数据类型 | 工程单位 | 核算模型与业务规则 |
|:---|:---|:---|:---|:---|
| 1 | 欧盟海关 CN 税号 | String | — | 欧盟海关税则编码，如 85042100 |
| 2 | 申报出口数量 | Decimal | 台/km/t | 国际贸易报关单提单实际数量 |
| 3 | 制造直接排放量 | Decimal | tCO2e | 厂内燃烧直接排放总量 |
| 4 | 外购电热间接排放量 | Decimal | tCO2e | 外购电力及前驱物隐含间接排放 |
| 5 | 单位产品隐含碳强度 | Decimal | tCO2e/单位 | $(Direct + Indirect) / 总产量$ |
| 6 | 欧盟 ETS 结算碳价 | Decimal | €/tCO2e | EEX 官方接口实时拉取最新周结算均价 |
| 7 | 国内已付碳成本折算 | Decimal | €/tCO2e | 中国碳市场价格汇率折算（€） |

| 9 | 预计应纳 CBAM 关税 | Decimal | €（欧元） | 应缴凭证数 ×（ETS 碳价 − 国内已付成本） |
| 10 | 情景类型 | Enum | — | 乐观 / 基准 / 悲观 |
| 11 | 申报包 Schema 校验结果 | Enum | — | 通过 / 违规（含节点级违规信息） |

#### 【5】核心数学模型与算法框架

```math
Cost_CBAM = [ (Direct_Em + Indirect_Em) / Output ] × Export_Qty × ( Price_EU_ETS - Price_Domestic_Paid )
Embedded_Carbon = ( Direct_Em + Indirect_Em ) / Output
Cert_Count = Export_Qty × Embedded_Carbon
Duty_payable = MAX( 0, Cert_Count × ( Price_EU_ETS - Price_Domestic_Paid ) )
Scenario = { 乐观: P_ETS × 0.85, 基准: P_ETS, 悲观: P_ETS × 1.15 }
```

**变量定义与取值约定：** 符合欧盟正式法规 EU 2023/956 条例；`Direct_Em` 为工厂直接化石燃烧排放；`Indirect_Em` 为外购电热及前驱物间接排放；`Export_Qty` 为出口实物总量；`Price_EU_ETS` 为欧盟碳价；`Price_Domestic_Paid` 为国内已付碳价。**若国内已支付碳成本等于或高于欧盟 ETS 碳价，则当期应缴 CBAM 关税凭证金额为 0（零关税入欧）**。

#### 【6】展示、对标与判定口径

- **碳价口径**：ETS 碳价以 EEX 官方接口最新周结算均价为准；碳价滞后超 24h 须标注时间戳。
- **抵扣口径**：国内已付碳成本须为可凭证明的全国碳市场配额费用或绿电附加成本。
- **零关税口径**：国内已付成本 ≥ 欧盟 ETS 碳价时应缴金额为 0，不允许出现负值退税。
- **情景口径**：情景碳价以当期价为基准按固定系数上下浮动，系数须在页面明示。

#### 【7】边界条件、异常处理与防错规则

> ⚠️ 【研发设计红线与强约束校验】
> - ETS 碳价超 24 小时未同步：触发 `E_EXT_ETS_PRICE_STALE`，界面标黄标注价格时间戳，允许基于最近有效历史均价测算。
> - 申报 XML 不符合欧盟 XSD 规范：触发 `E_VAL_CBAM_SCHEMA_INVALID`，提示具体节点 Schema 违规信息并**阻断申报包导出出境**。
> - 无实测排放数据：可一键套用 CBAM 官方默认排放因子库估算，但须显著标注"默认值估算"。
> - 计算结果为负：按 0 兜底，不产生退税逻辑。
> - 数据出境：跨境传输路径未经信息安全合规组审批前，导出功能保持关闭。

#### 【5】核心数学模型与算法框架

```math
E = Q × EF_effective(t)                                     按业务发生时间匹配生效版本因子
Valid = today ∈ [ effective_from, effective_to ]            有效期判定
Fresh_rate = N_valid / N_total × 100%                       因子新鲜度（NSM-CF-FACTOR-FRESH）
EF_match = PRIORITY( Ecoinvent_v38, CLCD_02, NDRC_fallback ) 匹配优先级
```

**变量定义与取值约定：** `EF_effective(t)` 为按业务发生时间匹配的生效版本因子；因子新鲜度目标为过期因子计数占比 ≥ 99%；匹配优先级为硬约束，不允许自定义调整顺序。

#### 【6】展示、对标与判定口径

- **来源口径**：集团自有因子必须附检测报告或第三方声明，缺一不可生效。
- **分级口径**：原辅料与电力因子 INTERNAL，Ecoinvent 跨境因子 SENSITIVE（含供应商来源）。
- **新鲜度口径**：因子库新鲜度以过期因子计数占比衡量，目标值 ≥ 99%。

#### 【7】边界条件、异常处理与防错规则

> ⚠️ 【研发设计红线与强约束校验】
> - 因子取值 ≤ 0：前端即时拦截，触发 `E_VAL_ENERGY_NEGATIVE` 类校验。
> - 因子超出有效期：触发 `E_VAL_FACTOR_EXPIRED`，标红因子标签并禁用"选用"按钮，提示"该因子已过期，请升级最新库"。
> - 集团自有因子缺检测报告或第三方声明：仅可保存为草稿，不可生效。
> - 版本生效区间重叠：前端拦截阻断保存。
> - Ecoinvent 授权到期：触发 `E_EXT_ECOINVENT_LICENSE`，自动降级使用 CLCD 因子兜底。
