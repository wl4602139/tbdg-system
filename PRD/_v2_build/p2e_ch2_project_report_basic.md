Deviation = ( P_actual - P_design ) / P_design × 100%      实测功率与设计基线偏差

### 3. 项目运行评估

#### 【1】定位与架构角色

- **功能定位**：遵循国际通用 IPMVP 测量与验证（M&V）规程，测算节能量、节约费用与动态投资回收期，形成节能技改项目效益闭环。
- **承载角色**：技改项目经理、P2 园区能碳专员、P6 外部审计机构（只读核验）。
- **页面路由**：`/monitor/project/evaluation`；子页 `/storage`、`/pv`、`/heatpump`、`/hvac`。
- **上游依赖**：项目档案管理设计指标、实时监控实测能耗、财务节能现金流数据。
- **下游输出**：节能效益评估状态机流转结论、零碳工厂自评估佐证材料。

#### 【2】业务场景与用户故事

- **业务场景**：年度节能技改项目效益复盘场景，需按 IPMVP 规程建立基线能耗模型，排除产量与气象波动影响后测算真实节能量。
- **用户故事**：
  - As a **技改项目经理**，
  - I want **按 M&V 四要素测算节能量与考虑贴现率的动态投资回收期**，
  - So that **我能客观证明技改投资效益并支撑下一年度技改立项**。

#### 【3】功能规格与交互契约

- **M&V 测算四要素**：
  - **基准期能耗**：改造前可验证的基线能耗（不少于 12 个月数据，【待补充】）。
  - **报告期能耗**：改造后实际计量能耗。
  - **调整量**：依据产量、天气等独立变量对基准期能耗的修正值。
  - **节能量**：$E\_saved = 基准期调整后能耗 − 报告期能耗$；动态投资回收期 = 项目投资额 / 年节约费用。
- **子模块划分**：`3.1 储能运行评估`、`3.2 光伏运行评估`、`3.3 热泵运行评估`、`3.4 空调运行评估`。
- **评估状态机可视化**：项目立项 → 建设施工 → 并网试运行 → 稳定运行 → 已完结；并网试运行需满足 90 天 M&V 连续采数，验收通过方可流转至"稳定运行"。
- **回归模型展示**：展示基准期能耗与独立变量（产量、度日数）的回归拟合优度 $R^2$，$R^2 < 0.75$ 时提示基线模型可靠性不足。

#### 【4】页面字段字典与数据契约

| 序号 | 字段中文名称 | 数据类型 | 工程单位 | 校验与约束规则 |
|:---|:---|:---|:---|:---|
| 1 | 基准期调整后能耗 | Decimal | tce | 基于不少于 12 个月数据建立回归模型 |
| 2 | 报告期实际能耗 | Decimal | tce | 改造后实际计量值 |
| 3 | 工况修正量 | Decimal | tce | 依据产量、气象等独立变量修正 |
| 4 | 节能量 | Decimal | tce | 基准期调整后能耗 − 报告期能耗 |
| 5 | 年净节能现金流 | Decimal | 万元 | 节能量 × 能量单价 − 运维成本 |
| 6 | 贴现率 | Decimal | % | 基准取值 8% |
| 7 | 动态投资回收期 | Decimal | 年 | $ln(CF/(CF − I_0 × r)) / ln(1 + r)$ |
| 8 | 回归拟合优度 | Decimal | — | $R^2$，低于 0.75 提示模型可靠性不足 |
| 9 | 评估状态 | Enum | — | 立项 / 施工 / 并网试运行 / 稳定运行 / 已完结 |
| 10 | 连续采数天数 | Integer | 天 | ≥ 90 天才允许流转至稳定运行 |

#### 【5】核心数学模型与算法框架

```math
E_saved = ( E_baseline - E_post ) ± ΔE_adj                        节能量
PBP_dynamic = ln( CF / ( CF - I_0 × r ) ) / ln( 1 + r )          动态投资回收期（考虑贴现率 r）
E_baseline = f( X_prod, X_hdd, X_cdd )                          基准期能耗回归模型
R² = 1 - SS_res / SS_tot                                        回归拟合优度
```

**变量定义与取值约定：** `E_baseline` 为基准期调整后能耗；`E_post` 为改造后实际能耗；`ΔE_adj` 为生产工况修正量；`I_0` 为技改初次投资；`CF` 为年净节能现金流；`r` 为贴现率（基准 8%）。依据国际 IPMVP 规程选项 B/C 建立基线能耗模型，排除气象温湿度与产量波动影响。

#### 【6】展示、对标与判定口径

- **基线口径**：基准期数据不得少于 12 个月，不足时评估功能置灰。
- **调整口径**：调整量必须基于统计显著的独立变量（产量、度日数）计算，不接受人工拍脑袋修正。
- **回收期口径**：以动态投资回收期（含贴现）为唯一对外口径，静态回收期仅作内部参考。
- **状态口径**：并网试运行阶段须连续采数 ≥90 天方可流转，流转动作写入审计日志。

#### 【7】边界条件、异常处理与防错规则

> ⚠️ 【研发设计红线与强约束校验】
> - 缺少基准期能耗记录：触发 `E_VAL_PRJ_MV_BASELINE_EMPTY`，阻断评估并提示"必须录入技改前至少 12 个月的基准期负荷数据"。
> - 基准期数据点少于 12 个月：评估按钮置灰，不允许强行测算。
> - 现金流小于等于投资额与贴现率乘积：动态回收期公式失效，输出"投资效益不成立，需重新评估"。
> - 连续采数不足 90 天：状态流转按钮置灰。

#### 【8】QA 自动化验收准则（Gherkin BDD）

```gherkin

  Scenario: 缺少基准期数据阻断评估
    Given 某技改项目尚未录入改造前的基准期能耗记录
    When 用户点击"启动 M&V 效益评估"
    Then 系统阻断评估并返回 E_VAL_PRJ_MV_BASELINE_EMPTY
    And 页面提示"必须录入技改前至少 12 个月的基准期负荷数据"

  Scenario: 动态投资回收期测算
    Given 项目初次投资 I_0、年净节能现金流 CF 与贴现率 r 均已录入

    And 贴现率基准取值 8%

    Then 流转按钮置灰不可点击
    And 连续采数满 90 天后按钮方可激活
```

### 4. 零碳工厂自评估

#### 【1】定位与架构角色

- **功能定位**：构建三层穿透的零碳工厂自评估体系，输出星级评定结果与整改清单，是集团零碳建设成效的权威量化抓手。
- **承载角色**：P2 园区能碳专员（填报）、二级公司（复核）、P1 集团决策层（审批）。
- **页面路由**：`/monitor/project/self-assessment`。
- **上游依赖**：指标管控、用能结构分析、碳排监测、因子库、绿证核销凭证、ISO 体系证书。
- **下游输出**：星级评定结果、领导驾驶舱星级分布数据、对标管理零碳综合得分输入。

#### 【2】业务场景与用户故事

- **业务场景**：年度零碳工厂评价场景，各园区按 6 大维度提交佐证材料，系统自动计分并分级评级，集团据此认定零碳工厂名单。
- **用户故事**：
  - As a **P2 园区能碳专员**，
  - I want **按 6 大维度 100 分细化考核表上传佐证材料并由系统自动计分评级**，
  - So that **我能清晰掌握本园区零碳建设短板并针对性整改**。

#### 【3】功能规格与交互契约

**三层评估架构**：第 1 层集团大盘雷达与星级分布 → 第 2 层二级公司总分达标率 → 第 3 层工厂 6 大维度 100 分细化考核表。

- **评级星级标准**：五星级（≥90 分）、四星级（80~89 分）、三星级（70~79 分）、未达标（<70 分）。

|:---|:---|:---|:---|

| 产业分母隔离 | 变压器按 kVA / 万kVA 汇算；线缆按 km·mm² 汇算，严禁跨产业混算 |
| 输出指标 | 单位产品综合能耗 / 电耗 / 蒸汽消耗 / 天然气消耗 / 水耗 5 项，细化到产品型号 |
| 对比列 | 同比、环比、与准入基准偏差 |
| 除零拦截 | 月产量为 0 时单耗显示 `--`，严禁 NaN 或白屏 |

- **产业分离呈现**：变压器与线缆单耗在报表中以两个独立区块呈现，不共用列。
- **型号级下钻**：支持从产品大类下钻至规格型号级明细行。

#### 【4】页面字段字典与数据契约

| 序号 | 字段中文名称 | 数据类型 | 工程单位 | 校验与约束规则 |
|:---|:---|:---|:---|:---|
| 1 | 产业分类 | Enum | 变压器/线缆 | 决定分母量纲，禁止跨产业同列 |
| 2 | 产品大类 | Enum | — | 变压器按高压/中低压/干变；线缆按拉丝/交联/其他 |
| 3 | 产品规格型号 | String | — | ERP 物料主数据编码 |
| 4 | 合格品产量 | Decimal | kVA 或 km·mm² | ≥ 0，为 0 时单耗显示 `--` |
| 5 | 单位产品综合能耗 | Decimal | tce/万kVA 或 tce/万km·mm² | $E / M$ |
| 6 | 单位产品电耗 | Decimal | kWh/kVA 或 kWh/km·mm² | $Q_电 / M$ |

#### 【5】核心数学模型与算法框架

```math
e = E / M                                     单位产品综合能耗
q_media = Q_media / M                         单位产品各介质消耗
MoM = ( e_t - e_{t-1} ) / e_{t-1} × 100%      环比
YoY = ( e_t - e_{t-12} ) / e_{t-12} × 100%    同比
Gap = e_t - Benchmark_admission               与准入基准偏差
Guard: M = 0 → "--"                           除零拦截
```

**变量定义与取值约定：** `M` 为当期合格品产量，变压器以 kVA / 万 kVA、线缆以 km·mm² / 万 km·mm² 计量；变量纲随产业分类严格隔离。

#### 【6】展示、对标与判定口径

- **分母孔径铁律**：变压器以 kVA/万 kVA 汇算，线缆以 km·mm² 汇算，严禁跨产业混算。
- **对比口径**：同比为同型号去年同期，环比为同型号上月。
- **偏差口径**：与准入基准偏差基于国家准入先进值计算。
- **状态口径**：按标杆值/基准值三色判定。

#### 【5】核心数学模型与算法框架

```math
C_scope1 = Σ ( FC_i × NCV_i × CC_i × OF_i × 44/12 )      直接排放
C_scope2 = Q_grid × EF_grid + Q_heat × EF_heat          间接排放
C_total = C_scope1 + C_scope2                            总排放量
C_net = MAX( 0, C_total - E_green × EF_grid )            抵扣后净排放量
Hash = SHA256( ReportContent )                           报告哈希存证
```

**变量定义与取值约定：** 排放因子均取因子库当前生效版本；`C_net` 按 0 兜底防止负值。

- **抵扣口径**：绿电抵扣需具备物理可溯源凭证，无凭证的绿证核销量单独列示。

> ⚠️ 【研发设计红线与强约束校验】
> - 因子过期：触发 `E_VAL_FACTOR_EXPIRED` 拦截生成，提示升级因子库。

> - 报告哈希比对失败：触发 `E_AUDIT_HASH_BROKEN`，锁定当事单据并标记数据被篡改。

#### 【5】核心数学模型与算法框架

```math
Cost = Q × P_version( t )                      按业务发生时间匹配对应生效版本单价
E_tce = Q_media × k_version( t )               按介质匹配对应生效版本折标系数
Guard: [ from_new, to_new ] ∩ [ from_old, to_old ] = ∅    生效区间不可重叠
Strategy = 重算 ? Recalculate( history ) : Apply( future_only )
```

**变量定义与取值约定：** `P_version(t)` 与 `k_version(t)` 为按业务发生时间匹配的版本化参数；版本生效区间严格有序且不可重叠；变更影响策略为必填项。

#### 【6】展示、对标与判定口径

- **版本口径**：任何计算均按业务发生时间匹配当时生效版本，严禁使用"当前版本"倒推历史。
- **审计口径**：新增/变更/废止全程留痕（修改人、时间、依据标准）。
- **影响口径**：系数变更须显式选择"重算历史"或"仅新周期生效"，不得默认。
- **审批口径**：未经审核的参数不得生效。

#### 【7】边界条件、异常处理与防错规则

> ⚠️ 【研发设计红线与强约束校验】
> - 新版本生效区间与在效版本重叠：前端即时拦截并阻断保存。
> - 参数数值为 0 或负数：触发 `E_VAL_ENERGY_NEGATIVE` 类校验拦截。
> - 变更影响策略未选择：保存按钮置灰。
> - 未审批参数被引用：核算引擎忽略该版本并触发 `E_VAL_FACTOR_EXPIRED` 类告警。
