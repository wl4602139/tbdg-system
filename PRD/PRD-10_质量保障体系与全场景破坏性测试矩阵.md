## 一、 10 条混沌与破坏性测试用例 (Chaos / Destructive Matrix)

| 用例编号 | 测试类别 | 故障注入与极限输入 | 预期防御与恢复行为 | 判定标准 |
|:---|:---|:---|:---|:---|
| **TC-DS-01** | 极值注入 | 产量输入 1e10 超大值及 1e-9 极微量 | 算法平稳处理，数据库无溢出，UI等比呈现 | 通过清零 |
| **TC-DS-02** | 除零防御 | 报工产量输入 0，计算单耗与产值比 | 拦截除零，单耗显示“--”，严禁白屏崩溃 | 通过清零 |
| **TC-DS-03** | 双击防刷 | 100ms 内连续快速点击提交 3 次 | Redis 分布式锁拦截后两笔，仅首笔入库 | 通过清零 |
| **TC-DS-04** | 负数拦截 | 录入用电量 -1000 kWh | 前端即时红框高亮阻断，禁止发送请求 | 通过清零 |
| **TC-DS-05** | 采集断网 | 切断变电站边缘一体机网络 72 小时 | 本地 SQLite 暂存，网络恢复后断点续传 | 通过清零 |

| **TC-DS-07** | 慢SQL治理 | 注入千万级跨年聚合时序慢查询 | 耗时 > 3s 自动告警并记录慢日志 | 通过清零 |
| **TC-DS-08** | 双机容灾 | 主数据库宕机模拟故障转移 | 备库 $\le 30$ 秒内接管，数据零丢失 (RPO=0) | 通过清零 |
| **TC-DS-09** | 越权防御 | 伪造 Token 越权访问 CBAM 申报底表 | 网关拦截并记录 E_AUTH_RBAC_FORBIDDEN | 通过清零 |
| **TC-DS-10** | 报文防篡改 | 篡改 CBAM XML 文件的哈希指纹 | 导出引擎阻断，提示签名无效 | 通过清零 |

## 二、 四套环境模型与准出标准

- **环境模型**：DEV (开发联调) ➔ TEST (全量自动化与破坏性压测) ➔ STG (预发仿真与数据脱敏) ➔ PROD (生产环境)；
- **发布红线**：P0 阻断级缺陷必须 100% 清零，P1 严重级缺陷清零率 $\ge 98\%$。\n
