# 📋 企业级 PRD 研发准入 (DoR) 与交付准出 (DoD) 质量门禁检查清单

> 本清单用于在 PRD 评审会（研发准入）与系统上线发布会（交付准出）中执行一票否决式审查。

---

## 一、 研发准入前置条件门禁 (DoR - Definition of Ready)

在研发团队排期接单前，PRD 文档必须逐项通过以下 **10 项硬性检查项**（任一不符合直接打回修整）：

| 序号 | 检查领域 | 门禁标准 (Pass Criteria) | 判定 (Pass/Fail) | 责任角色 |
|:---:|:---|:---|:---:|:---:|
| **1** | **未决占位符清零** | 全文检索 `待确认`、`待补充`、`TBD`、`FIXME`、`xxx`、`暂定`，命中数为 **0** | [ ] | PM |
| **2** | **路由物理对齐** | 文档中的所有页面与详情路由路径，与前端代码目录物理路径 **100% 对应** | [ ] | PM / 前端 |
| **3** | **字段字典完备性** | 所有数据表格与表单字段均包含英文 Key、类型、单位、精度、来源与校验规则 | [ ] | PM / 架构 |
| **4** | **极限除零安全防护** | 所有除法算式、单耗比值明确声明分母为 0 时的兜底处理（统一安全返回 `--`） | [ ] | PM / 算法 |
| **5** | **全分支业务状态机** | 核心业务实体包含草稿、生效、驳回、失效、熔断全分支，无未定义状态 | [ ] | PM / 架构 |
| **6** | **白名单枚举清晰** | 权限、单位、工序限制全部给出明确名单枚举，严禁“根据实际情况定” | [ ] | PM |
| **7** | **统一受控错误码** | 异常拦截与前端错误均绑定受控错误码（如 `E_...`），无未知报错 | [ ] | 架构 / 后端 |
| **8** | **BDD 验收用例覆盖** | 每个功能点包含正向主流程、极限除零、逆向拦截三类 Gherkin 用例 | [ ] | QA / PM |
| **9** | **量化 NFR 指标** | 页面 LCP、P95 响应时间、导出上限具备明确秒级指标，无模糊修饰词 | [ ] | 架构 / PM |
| **10** | **四方会签闭环** | PM、架构师、前端主管、QA 主管在文档审签栏完成签字确认 (Sign-off) | [ ] | 全体主管 |

---

## 二、 交付验收准出门禁 (DoD - Definition of Done)

系统上线投产前，对照 PRD 逐项验收交付成果：

| 序号 | 验收领域 | 准出标准 (Exit Criteria) | 判定 (Pass/Fail) | 责任角色 |
|:---:|:---|:---|:---:|:---:|
| **1** | **自动化测试全绿** | PRD 中定义的 Gherkin BDD 用例 100% 转换为自动化测试脚本且通过率为 100% | [ ] | QA |
| **2** | **破坏性测试无缺陷** | 针对除零、负数输入、高并发防刷、断网重连等边界注入测试 0 遗留缺陷 | [ ] | QA / 后端 |
| **3** | **客观中立静态扫描** | 全量代码与文本中主观定性褒贬评价词汇（“优良/落后/表现优异”）扫描为 **0** | [ ] | QA / 前端 |
| **4** | **工业设计规范符合度** | 表格强制 44px 行高、按钮/输入框标准尺寸、色彩字典 100% 符合设计系统 | [ ] | 前端 / UI |
| **5** | **接口与数据契约一致** | 生产接口入参出参与 PRD OpenAPI 契约 100% 一致，无额外字段泄露 | [ ] | 架构 / 后端 |
| **6** | **数据出境与商密合规** | 涉及对外/跨境申报时，严格字段白名单机制已落地，L3~L4 商密已脱敏 | [ ] | 安全 / 合规 |
| **7** | **性能压测全面达标** | 首屏渲染 $\le 3.0$s，P95 查询响应 $\le 800$ms，十万行导出 $\le 30$s 达成 | [ ] | DevOps / 后端 |
| **8** | **用户操作手册与归档** | 基于最终 PRD 生成用户操作手册，变更记录原位维护入档 | [ ] | PM / 文档专员 |
