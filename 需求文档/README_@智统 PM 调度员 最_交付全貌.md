### 一、需求核心目标与项目工程现状

#### 1.1 需求核心目标

用户（呆子/组长）明确指出最终交付的 Markdown 报告中**缺失页面级模块结构说明**，要求补充以下三要素：

| 补充维度 | 具体含义 | 用户诉求本质 |
| :--- | :--- | :--- |
| **页面中有哪些模块** | 每个页面的功能区块组成（如：顶部 KPI 卡片区、中部图表区、左侧树形导航区、右侧联动面板等） | 建立“页面 → 模块”的映射关系 |
| **模块有哪些数据** | 每个模块承载的具体数据实体与字段（如：卡片展示“综合能耗 tce”、表格展示“各经营单位消耗明细”） | 建立“模块 → 数据”的绑定关系 |
| **模块的展示方式** | 各模块的视觉呈现形态（卡片、表格、折线图、饼图、条形图、树形控件、地图等） | 建立“数据 → 展示形态”的最终呈现关系 |

**核心价值**：将已有的 **路由清单（老高交付）** 与 **数据需求（阿亮交付）** 两个维度的成果，**补齐第三个维度——页面布局/模块结构**，最终形成 `路由 → 页面 → 模块 → 数据 → 展示方式` 五级完整透视链。
